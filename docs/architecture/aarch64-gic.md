# AArch64 GICv2 interrupt foundation

> Implementation: integrated and locally reverified R4.4 QEMU `virt,gic-version=2,secure=off` single-BSP slice; physical hardware is unverified

The supported ARM64 emulator profile pins a legacy MMIO GICv2 with one CPU. FinnOS identity-maps the complete distributor window at `0x0800_0000` and CPU-interface window at `0x0801_0000` as EL1 RW/NX Device-nGnRnE memory before accessing either controller. The fixed layout is part of the QEMU target profile, not a hardware-discovery interface; device-tree/ACPI discovery and GICv3 remain R5 work.

Initialization runs after the owned EL1 address space is active and while DAIF.I remains masked. It disables the CPU and distributor interfaces, derives a bounded interrupt count from `GICD_TYPER`, disables and clears PPI/SPI state, clears banked SGI pending state, assigns SGI 1 a fixed priority, programs the CPU priority mask/binary point, and readback-verifies the enabled interfaces. The `secure=off` QEMU model exposes the legacy single interrupt group, so SGI 1 uses the primary IAR/EOIR path; this is not a general secure/non-secure routing policy.

The existing 816-byte vector frame handles current-EL SPx IRQ source 5 and preserves x0-x30, q0-q31, FPCR/FPSR, ELR, and SPSR. Dispatch enters the architecture-neutral `InterruptContextGuard`, reads the acknowledge token exactly once, and writes the complete token exactly once to EOIR for a real interrupt. Special IDs 1020-1023 receive no EOI. Unexpected real IDs are EOI'd before the fatal path so an acknowledged source is not stranded active. The handler performs no allocation, locking, scheduling, or serial output.

The isolated `test-arm64-gic` mode proves a real controller lifecycle with self-targeted SGI 1. It observes ID 1023 before delivery without EOI, arms an atomic state, issues the SGI while IRQ is masked, verifies the banked source-pending bit, clears only DAIF.I, and spins in assembly until the IRQ handler publishes completion. The handler must arrive through vector source 5, observe the seeded x19 frame value, acknowledge ID 1 from BSP source zero, EOI the exact raw token, and return through `eret`. Thread code immediately remasks IRQ and requires one delivery, one EOI, restored interrupt depth, no context fault, the expected SPSR mask state, and a second no-pending ID 1023. Semihosting success is unreachable without that hardware-controlled state transition.

Production boot initializes the controller but leaves all asynchronous delivery masked because no production IRQ consumer exists yet. This slice does not implement the architectural timer, timekeeping, external device routing, MSI/GICv2m, GICv3, SMP/IPIs, nesting, preemption, task contexts, EL0 delivery, discovery, shutdown, or physical hardware support.
