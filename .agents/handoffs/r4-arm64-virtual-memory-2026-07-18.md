# Agent Handoff: R4.3 ARM64 virtual memory

- Objective: replace inherited firmware translations with FinnOS-owned ARM64 EL1 stage-1 tables while preserving the R4.1 exception and R4.2 early-memory boundaries.
- Starting state: `f74fc49` on `main`, with locally verified but uncommitted R4.1/R4.2 changes stacked. `.freebuff/` was pre-existing and remains untouched.
- Task state: locally verified; review-ready only after the stacked work is integrated and CI passes.
- Scope delivered: four-level 4 KiB low-48-bit TTBR0 identity tables; transactional 64-page allocator-owned table pool; Normal-WBWA, Device-nGnRnE, and Normal-NC attributes; EL1-only W^X/NX; null and 4 KiB early-stack guards; MAIR/TCR/TTBR/SCTLR activation; table cache cleaning, barriers, and TLB invalidation; software walks; exact control-register readback; deterministic QEMU normal and four-fault evidence; tooling, CI, tests, and documentation.
- Non-goals preserved: higher-half relocation, EL0/user address spaces, ASIDs, block mappings, dynamic VM, table reclamation, heap, KASLR, secure/verified boot, GIC, timer, task contexts, SMP, physical hardware, and UEFI LoaderData reclaim.
- Mapping contract: text is EL1 RX; rodata and handoff/map/RSDP storage are EL1 R/NX; data, BSS, stack, and table storage are EL1 RW/NX; PL011 is Device RW/NX; optional framebuffer is Normal-NC RW/NX; physical aliases with differing permissions or memory types are rejected; page zero and both guards are absent.
- Activation contract: the implementation rejects unsupported 4 KiB/PARange/endian configurations, validates inherited identity translations for every live range, cleans used descriptor pages to PoC, uses a stack-free MMU-off assembly transition, zeros TTBR1, enables M/C/I/SA/WXN, and requires literal TTBR0/TCR/MAIR/SCTLR/TTBR1 readback.
- Fault contract: only an exactly armed current-EL synchronous abort may resume. EC, IL, FnV, S1PTW, FSC class, WnR, FAR, ELR, source, and atomic state must all match. The isolated mode proves null-read translation, low-guard-read translation, text-write permission, and data-execute permission faults; unexpected exceptions remain fatal.
- Independent review: three ARM architecture/source/security reviewers reported no P0 findings. Their P1 findings were fixed: exact normalized-line markers, invalid syndrome-bit rejection, exact root/TTBR1/control validation, literal activation readback, cross-mode leakage rejection, and adversarial tests. The selected four-level 48-bit design was accepted as an intentional bounded alternative to the earlier three-level proposal.
- Runtime evidence (2026-07-18, QEMU 11.0.2/Homebrew AAVMF, macOS ARM64): `./tools/finn test-page-tables --target arm64-qemu` exited 0 after `ROOT=TTBR0=0x40000000`, `TTBR1=0`, `TCR=0x0000000480903510`, `MAIR=0x00000000004400ff`, `SCTLR=0x0000000030d8198d`, 64 reserved/9 used table pages, 160 mapped pages, and all four ordered hardware aborts. The rerun required execution outside the filesystem sandbox because macOS DiskManagement returned `Device not configured` inside it.
- Regression evidence: ARM normal boot, memory, controlled exception, and fatal diagnostic modes previously passed after MMU integration; x86 first boot and page tables passed with status 33. `cargo test -p finn-kernel` passed 80 tests before the final review hardening. After hardening, 57 Python tooling tests, focused 6 ARM exception tests, ARM page-table cross-check/strict Clippy, formatting, and `git diff --check` passed. Final aggregate gates are recorded in the task response/state after execution.
- Limitations and residual risks: local QEMU `virt`/AAVMF evidence only; current QEMU exposes no framebuffer, so Normal-NC framebuffer behavior has descriptor tests but no runtime device evidence; the address space is immutable and its handle has no reclamation path; guards cannot diagnose stack exhaustion because exception entry uses the current stack; no alternate CPU/firmware or physical coherency evidence exists.
