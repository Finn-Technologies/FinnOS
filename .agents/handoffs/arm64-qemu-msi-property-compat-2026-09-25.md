- Risks/regressions to watch:
  - The probe runs one short-lived QEMU invocation per ARM64 command construction. It is cheap, but a wedged or absent QEMU must stay bounded by the timeout and the `OSError` path; both are covered by tests.
  - If a future emulator gains an `msi` property with different accepted values, `gicv2m` may be rejected by value rather than by name. The probe checks presence, not validity, so an emulator that advertises `msi` but not `gicv2m` would still fail at launch. Pinning a minimum QEMU version in CI is the alternative if that ever matters.
  - Do not reintroduce an unconditional machine property. The failure mode is invisible locally by construction, because the development emulator is newer than the CI emulator.
