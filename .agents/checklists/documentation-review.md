# Documentation Review

- [ ] Present tense only for inspected and, where required, executed behavior.
- [ ] Distinguish implemented, unverified, partial, prototype, planned, blocked, unknown.
- [ ] Validate every command and local link.
- [ ] Keep canonical status/roadmap/architecture boundaries; link instead of duplicate.
- [ ] State architecture, emulator/hardware scope, profile, date, and commit for evidence.
- [ ] Update limitations, tests, and agent skills with behavior changes.
- [ ] Avoid permanent hard-coded test counts unless tied to an audit snapshot.
